## APA-1 — Non-finite battery power becomes charging (confirmed, medium)

Location: `sim/src/main/java/com/photonspark/sparkmotors/sim/electric/BatteryModel.java`, through `VehicleDynamics.clamp`.

On the 400 V / 60 kWh pack at 50% SOC, 20 C, with a 0.0125 s step, each request `NaN`, `+Infinity` and `-Infinity` adds **1,680 J**. The reported terminal transfer is **-1,779.53125 J**. Non-finite clamp inputs become the lower bound, converting malformed input into a large charging request.

The independent runner compiled actual simulation sources without mocks. Its seven suites produced **4 passes, 3 failures and 22,171 assertions**. All three failures are variants of this one defect. The passing suites include 4,000 seeded finite battery conservation cases, every charger/vehicle budget and interlock combination, grid-paid cold preheat, and 6,000 seeded passive chassis energy cases.

This is a reproducible numerical API defect, not a demonstrated normal-player charge exploit. Driver packets do not directly supply terminal watts and finite steering validation exists. Reject non-finite power or use explicit zero-demand fallback; never silently convert invalid input into charge. Keep the regression failing until production behavior is fixed.

[Independent execution](https://github.com/CesarPetrescu/AutoPropulsion-Age/actions/runs/34218506365). Reproduce:

```sh
mkdir -p build/qa/classes
find sim/src/main/java -name '*.java' > build/qa/sources.txt
javac -d build/qa/classes @build/qa/sources.txt tools/qa/IndependentAudit.java
java -cp build/qa/classes IndependentAudit
```

## APA-2 — Stale client orientation after fixture reset invalidates handling assertion (confirmed on 0.6.0)

Location: `src/gametest/java/com/photonspark/sparkmotors/gametest/HandlingClient.java`, phase 2 reset and phase 1 heading reference.

The native FWD test repeatedly failed with `A key must turn toward driver left in Minecraft world coordinates: 0.0`. One unchanged rerun passed. Diagnostic logging was added without changing production code or relaxing assertions.

At FWD sample 99 the client heading/reference was **-16.13602 degrees**, while the server was at **0 degrees**. At sample 109 the server had turned to **-7.88888 degrees**, yaw rate **-0.72189 rad/s**, while the client showed **-7.02771 degrees**. The server actually turned left; the test compared the client against its stale heading and observed the wrong relative sign during its short measurement window.

The fixture performs server-side `saveWithoutId`, `load`, and `moveTo(..., yaw=0)` between layouts. Investigate authoritative reset/interpolation synchronization, and make the harness require client/server heading convergence before measuring the next turn. Do not hide this by loosening the steering threshold. Ordinary gameplay reproduction beyond this reset path remains unestablished. The later 0.6.1 main CI passed; this does not establish the exact root cause was fixed.

Evidence: initial [34216672033](https://github.com/CesarPetrescu/AutoPropulsion-Age/actions/runs/34216672033), repeat [34218506415](https://github.com/CesarPetrescu/AutoPropulsion-Age/actions/runs/34218506415), and instrumented [34219448557](https://github.com/CesarPetrescu/AutoPropulsion-Age/actions/runs/34219448557), artifact `evidence-client-handling`.

## APA-3 — Historical Fabulous graphics path crashes (confirmed historical path, cause not fully isolated)

Only reproduced on playable-foundation `2995e16`. Fast and Fancy clients drove approximately 76.83 m and 77.66 m respectively and captured their required screenshots. Fabulous connected, then crashed because `LevelRenderer.getTranslucentTarget()` was null when `RenderTarget.bindWrite` was called.

Its `ClientSmoke` changes the graphics option after joining the world without an accompanying renderer rebuild. That is a plausible harness cause, not proof of a normal video-menu or current-main crash. Repeat with Fabulous selected before world loading and through Minecraft's proper video-settings path before attributing the failure to vehicle rendering. Do not use this historical branch as the current release baseline.
